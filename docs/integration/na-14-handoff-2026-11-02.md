## C. Database

Migration: `0008_booking_metadata_venue_settings.sql`.

| Bảng/cột | Schema |
| --- | --- |
| `reservations.guest_type` | VARCHAR(20), ASCII binary, NOT NULL DEFAULT NEW, CHECK REGULAR/NEW |
| `reservations.is_birthday` | TINYINT(1), NOT NULL DEFAULT 0, CHECK 0/1 |
| `reservations.late_confirmed_at` | DATETIME(3), NULL DEFAULT NULL, UTC |
| `venue_settings` | organization_id/venue_id BIGINT UNSIGNED, key VARCHAR(100) ASCII binary, value JSON NOT NULL |
| Uniqueness | PRIMARY KEY (venue_id, key) |
| Tenant FK | (organization_id, venue_id) tham chiếu venues(organization_id, id), ON DELETE CASCADE |

Backfill: RETURNING thành REGULAR; NEW, UNCLASSIFIED và NULL thành NEW. Không sửa giá trị classification cũ, không reset booking, birthday mặc định 0 và thời điểm xác nhận trễ để NULL. SQL writers phải ghi classification và guest_type tương ứng trong cùng câu lệnh.

Settings là ba bản ghi: quick_times = [21:00,21:30,22:00,22:30], upcoming_minutes = 10, no_show_minutes lấy ngưỡng cũ của venue (mặc định 30). Venue đã chỉnh ngưỡng 45 vẫn giữ 45. ON DUPLICATE KEY không đổi value đã có.

Venue mới dùng `initializeVenueSettings(actor, connection)` lúc provisioning, hoặc được khởi tạo ở lần đọc settings đầu. Không dùng trigger. API DB role cần SELECT/INSERT/UPDATE trên venue_settings nếu dùng lazy initialization.

Chỉ chạy trên container MySQL 9.7.2 riêng `gam-na14-mysql-test`, host 127.0.0.1:33316. Không chạy migration/seed trên MySQL hiện có ở 3306 hoặc production. Test nâng cấp/dữ liệu mẫu tạo database tên `gam21_na14_*_test`, rồi dọn đúng database đó.

## D. API contract bàn giao cho Tú

Chi tiết đầy đủ và ví dụ: [docs/api.md](../api.md#na-14-booking-metadata-and-venue-settings).

- POST `/api/v1/bookings`, POST `/api/v1/bookings/direct`, PUT `/api/v1/bookings/:id`: nhận guestType (REGULAR/NEW) và isBirthday (boolean). Create mặc định NEW/false; PUT bỏ qua trường thì giữ nguyên. PUT vẫn yêu cầu các trường booking hiện hành và version.
- GET list/detail/search và mọi response booking trả guestType, isBirthday, lateConfirmedAt (UTC ISO string/null).
- GET `/api/v1/venues/:id/settings`: id phải trùng venue session; venue khác trả 404. GET `/api/v1/tables/catalog` cũng trả `venue.settings`. Chưa có endpoint sửa settings trong NA-14.

Request create:

```json
{"guestName":"Khách Sprint 2","partySize":4,"expectedAt":"2030-10-24T21:00:00+07:00","businessDate":"2030-10-24","sourceCode":"HOTLINE","guestType":"REGULAR","isBirthday":true}
```

Metadata response:

```json
{"classification":"RETURNING","guestType":"REGULAR","isBirthday":true,"lateConfirmedAt":null}
```

Settings response:

```json
{"venueId":1,"settings":{"quick_times":["21:00","21:30","22:00","22:30"],"upcoming_minutes":10,"no_show_minutes":30}}
```

| Task | Dữ liệu và lưu ý |
| --- | --- |
| TU-11 | Dùng upcoming_minutes cho mốc sắp tới; không đổi meaning status hiện có trong NA-14 |
| TU-12 | Đã có late_confirmed_at, response và adapter. Tú triển khai endpoint hành động riêng, dùng server UTC, kiểm quyền/version/status, audit và change_seq trong transaction. Gửi timestamp vào create/PUT thường bị 400 LATE_CONFIRMATION_READ_ONLY |
| TU-15 | Dùng guestType để đếm khách quen/mới, isBirthday cho dấu sinh nhật; export cũ vẫn giữ thống kê riêng UNCLASSIFIED lịch sử |
| TU-16 | Đọc quick_times từ settings/catalog; UI tiếp tục kiểm giờ nhận booking và ngày nghiệp vụ |

No-show: setting hợp lệ ưu tiên, fallback venues.no_show_warning_minutes. Catalog alias, booking timing và worker opt-in đọc cùng helper. `autoNoShowDue` chỉ là tín hiệu; BOOKED vẫn không tự biến thành NO_SHOW. Không bật worker hoặc tự nhả bàn trong task này.
